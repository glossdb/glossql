# docs — coverage inventories

Operational records of what the system covers and what it does not.
Each subfolder is an honest built / not-built statement for one
concern; the not-built half is the lightweight backlog. Nothing here is
normative language prose — SPEC.md keeps that role alone.

- [`onboarding/`](onboarding/README.md) — the path from a company's
  exports and definitions to a working glossed workspace; the current
  priority backlog.
- [`system/`](system/README.md) — the server across concerns: built,
  ruled out, known debts, and planned work with its triggers.
- [`quality/`](quality/README.md) — quality monitoring of the data and
  of the performance monitoring built on it.
