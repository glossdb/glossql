# The app door — server-rendered data apps, first app live

Date: 2026-08-07. The UX phase's first build, on the stack settled with
the project lead the same day: htmx strictly server-side, tera
hot-loaded templates, vega-lite + arrow-js as the only chart/data JS,
REST with the URL as the only state, one binary.

## What landed

`crates/apps`, mounted by serverd at `/app` beside `/mcp` and `/query`.
The design rules it hardens:

- **An app is a directory, not a manifest.** `apps/<name>/` in the
  workspace: `app.toml` (title, dataset), tera pages, `frames/*.sql`,
  `specs/*.vl.json`. No JSON representation layer, no content
  framework — the page is the app. Authors (agent or human) write only
  declarative artifacts; the wrapper's three JS islands are hand-written
  and ship embedded (vendored htmx 2.0.8, vega 6.2.0, vega-lite 6.4.3,
  vega-embed 7.0.2, apache-arrow 21 — offline, no CDN).
- **Frames are declared reads.** `GET /app/<app>/frames/<name>` runs
  the frame's SQL through the session's one-query streaming path
  (writes are structurally impossible there) as Human actor
  `app:<name>`, and streams Arrow IPC. URL params bind as plan
  placeholders (`$from` in SQL, `?from=…` on the URL) — typed values
  through the plan, never text spliced. A reference's own params are
  the author's defaults; the page URL overrides them. An unbound
  placeholder errors at read, naming itself.
- **The frame store holds each frame once.** Charts and tables bind to
  the same arrow table in the browser; a state change refetches only
  frames whose URL changed. Client-side reshaping is governed by
  judged behavior: flows may aggregate in-spec, ratios and stocks
  re-compose server-side — the rule rides the glossary, not the UI.
- **Drill is navigation.** A vega click writes one URL param and the
  server renders the narrowed state. No validation layer: template,
  engine, and browser errors each surface at their own read, in place.
- `Plane` moved from serverd into `glossql-session` — every door
  shares it.

## The live proof

`apps/cash` on run 8/9's fin2 workspace (booksql, 810k-row ledger),
against a second serverd on the same workspace files: billings by
month (64 months, `metric.billings()` summed as its flow gloss
allows), DSO by month (`metric.dso()` served as recorded — ratio rows
never regrouped), and click-a-month drill to the top-25 customer
breakdown riding the metric's own `customer_name` column. All three
frames stream IPC with bound params; the unbound case answers
`No value found for placeholder with name $month`. The crate's door
test covers the same arc on a fixture workspace: pages render through
shell + macros, params filter, `DROP TABLE` in a frame file refuses,
path escapes 404.

## Open, deliberately

The world-model explorer (glossary/functions/ATTEST pages in the
wrapper), the app-generation skill (the drill/slice/aggregate
conventions will take iterations, as the project lead expects from
v0.3 experience), codemirror (parked until SQL turns editable in the
UI), morphing swaps for in-place chart updates.
